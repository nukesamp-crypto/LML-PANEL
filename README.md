## 📌 معرفی پروژه

LML PANEL یک پنل وب فارسی برای مدیریت کاربران و ساخت کانفیگ‌های اتصال است.

این پروژه بر پایه Cloudflare Workers و پایگاه داده D1 طراحی شده و بخش‌های اصلی برنامه در قالب یک Worker اجرا می‌شوند.

## 🚀 آموزش نصب و راه‌اندازی

### مرحله اول: دریافت سورس کد

وارد مخزن رسمی پروژه شوید:

[دریافت سورس کد LML PANEL](https://github.com/nukesamp-crypto/LML-PANEL)

فایل برنامه را از مخزن دریافت کنید.

### مرحله دوم: ساخت Worker

۱. وارد داشبورد Cloudflare شوید.

۲. از بخش Workers & Pages، یک Worker جدید ایجاد کنید.

۳. نام دلخواه خود را برای Worker انتخاب کنید.

۴. پس از ایجاد Worker، وارد بخش ویرایش کد شوید.

۵. محتوای فایل برنامه را در ویرایشگر قرار دهید.

۶. تغییرات را ذخیره و Worker را Deploy کنید.

### مرحله سوم: ایجاد پایگاه داده D1

۱. در داشبورد Cloudflare وارد بخش D1 شوید.

۲. یک پایگاه داده جدید ایجاد کنید.

۳. به تنظیمات Worker برگردید.

۴. وارد بخش Settings و سپس Bindings شوید.

۵. یک اتصال D1 Database اضافه کنید.

۶. پایگاه داده‌ای را که ساخته‌اید انتخاب کنید.

۷. نام متغیر اتصال را دقیقاً برابر با DB قرار دهید.

**توجه:** نام متغیر اتصال باید دقیقاً DB باشد تا برنامه بتواند به پایگاه داده دسترسی پیدا کند.

### مرحله چهارم: استقرار نهایی

پس از تنظیم اتصال پایگاه داده:

۱. تغییرات Worker را ذخیره کنید.

۲. یک بار دیگر Deploy را انجام دهید.

۳. آدرس Worker خود را باز کنید.

۴. در انتهای آدرس، مسیر /panel را قرار دهید.

۵. صفحه مدیریت پنل را باز کنید و رمز عبور مدیر را تنظیم کنید.

### مرحله پنجم: بررسی عملکرد

پس از ورود به پنل، بخش‌های مختلف را بررسی کنید تا مطمئن شوید برنامه و پایگاه داده به‌درستی کار می‌کنند.

جداول موردنیاز پایگاه داده در اولین اجرا به‌صورت خودکار ایجاد می‌شوند و نیازی به ساخت دستی آن‌ها نیست.

## 🩺 رفع اشکال: خطای SSL / «اتصال ناامن» در بعضی سایت‌ها

اگر کانفیگ وصل می‌شود (مثلاً تلگرام یا یوتیوب کار می‌کند) ولی **بعضی سایت‌ها بالا نمی‌آیند** یا مرورگر خطای **«اتصال شما خصوصی نیست / Your connection is not private»** نمایش می‌دهد، این مشکل از پنل یا کانفیگ ‌**نیست**.

ورکر ترافیک TLS بین مرورگر شما و سایت مقصد را فقط عبور می‌دهد و هیچ دخالتی در گواهی امنیتی سایت‌ها ندارد. علت رایج این وضعیت **آلودگی DNS دستگاه** است: کلاینت (مثل v2rayNG) اسم سایت‌ها را به‌طور پیش‌فرض با DNS محلی/اپراتور ترجمه می‌کند و برای دامنه‌های فیلترشده یک IP جعلی دریافت می‌کند؛ اتصال به آن IP اشتباه باعث می‌شود مرورگر گواهی یک سرور ناشناس را ببیند و خطای SSL بدهد.

### ✅ راه‌حل در v2rayNG (اندروید)

در بخش **Settings** این موارد را اعمال کنید:

1. **Domain Strategy** ← روی `AsIs` قرار دهید (تا نام سایت‌ها روی گوشی ترجمه نشود و مستقیم به ورکر برسد).
2. **Enable local DNS** ← **روشن** کنید (تا درخواست‌های DNS از داخل تونل عبور کنند).
3. **Remote DNS** ← `https://dns.google/dns-query` یا `1.1.1.1`
4. **Domestic DNS** ← `8.8.8.8` یا `223.5.5.5`
5. **Mux** ← **خاموش** کنید (Mux با کانفیگ‌های WebSocket روی Workers با بسیاری از سایت‌ها ناسازگار است).
6. برای تست، Routing را روی **Global** بگذارید و v2rayNG را به آخرین نسخه به‌روزرسانی کنید.

### نکات تکمیلی

* فقط از کانفیگ‌های **پورت 443 (TLS)** استفاده کنید؛ کانفیگ پورت 80 بدون رمزنگاری است و ممکن است اپراتور در مسیر آن اختلال ایجاد کند.
* **تاریخ و ساعت دستگاه** باید دقیق باشد؛ ساعت اشتباه باعث خطای SSL در همه‌ی سایت‌ها می‌شود.
* آنتی‌ویروس‌ها یا VPNهای هم‌زمان دیگر را غیرفعال کنید (بعضی ترافیک HTTPS را بازرسی/MITM می‌کنند).
* اگر مشکل ادامه داشت، یک بار با Hiddify یا NekoBox تست کنید؛ این کلاینت‌ها به‌طور پیش‌فرض DNS را از سمت سرور انجام می‌دهند.
